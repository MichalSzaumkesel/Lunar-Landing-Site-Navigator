# Review R4: visionary (new ideas and pitch)

Read `tasks/_review.md` first, then `../CLAUDE.md` (the challenge and our feature table) and skim `src/components/` names to see what exists. Report file: `tasks/reviews/R4-visionary.md`. This role proposes, it does not audit code, so the finding format is relaxed: use ideas instead of findings.

Already decided or built (do not repeat): polar sky plot, panorama strip, sun-through-the-ridge loupe, Earth phase, event chips, timeline with Play, scenario cards with countdowns and metrics, slip slider, window map (sites by landing dates), mission rules form, 3D surface view with shadows, Moon map with day/night, site library, custom coordinates (approximate), share link, CSV export, optional sound cues, guided demo mode, Simple/Advanced switch with a skippable tutorial, "move the lander" horizon recompute and local sunlight heatmap (stretch).

Propose up to 12 NEW ideas that would impress a jury of NASA-minded judges in 2 to 3 minutes and fit a 30-second video, under these constraints: only scope B (static web app, no backend), no new data from scope A, buildable in at most 2 hours each by a Flash-class model plus review, honest labelling (synthetic or approximate where it applies), no claims about power or link availability. For each idea: name, the 5-second "wow" moment, what it uses from the existing code or data, effort (S/M/L), risk, and a one-line critical verdict (do it / maybe / skip) with the reason. Then:
- A 30-second video storyboard (shot list with seconds and on-screen text) using only features that exist or are decided.
- A 2-minute live demo script outline for the jury, including a fallback if the network or WebGL fails.
- Three options for the project tagline (under 10 words) and a one-paragraph pitch.
- Three sharp questions a NASA judge could ask about method and accuracy, with honest answers based on `CLAUDE.md` (physics notes) and the contract.
Be bold but disciplined: every idea must be demonstrable offline.
